The repository is an ordinary Rustic repository: you can inspect it and restore from it with the rustic command, without the scheduler. The commands below are filled in from each job's configuration. Passwords and credentials are never shown; they stay in the files your profiles and environment point to.

  • Listing and checking are safe at any time, also while the scheduler is running a backup. snapshots, ls and restore --dry-run read metadata only.
  • Do not run forget or prune by hand unless you mean to: they delete data and skip the scheduler's safeguards (preview, the job's snapshot scope, the removal limit). The in-container helper waits for the scheduler's repository lock; plain rustic does not.
  • Cold storage. On S3 Glacier Flexible Retrieval or Deep Archive, data must be retrieved before a restore or check --read-data can read it, which takes hours and costs money. This project has not tested a Glacier restore against AWS: read docs/restore.md and try it yourself before you depend on it.
  • The default check proves that the metadata is consistent, not that every data pack is intact. Only a restore, or check --read-data, proves that.
